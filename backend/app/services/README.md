# services/

Бизнес-логика backend Slack-MM2 Sync.

- backup/ — работа с файлами бэкапа, парсинг zip, хранение, обработка
- webhook/ — обработка и парсинг входящих вебхуков
- entities/ — парсинг сущностей, миксины, импорт в БД
- export/ — экспорт данных в Mattermost и другие системы

Каждый подмодуль содержит README с деталями структуры. 

## Ключевые архитектурные принципы

1. Однопроходный импорт: стадии строго последовательны (extracting → users → channels → messages → exporting → done), без обратных циклов и дополнительных фаз для реакций/вложений/эмодзи.
2. Реакции, вложения, custom emoji регистрируются внутри прохода сообщений (модуль `backup/messages_import.py`).
3. Прогресс-счётчики и метаданные обновляются только атомарной функцией `merge_job_meta` (см. `backup/meta_utils.py`), исключая lost update.
4. Любое добавление нового счётчика требует обновить root README, backend README и mini-интеграционный скрипт.
5. Отсутствие feature-flags: функциональность всегда активна после мержа.

## Где искать что
| Подсистема | Файл/директория | Назначение |
|-----------|-----------------|------------|
| Оркестрация импорта | `backup/orchestrator.py` | Переход стадий, вызовы парсеров, финальная консолидация totals |
| Atomic meta merge | `backup/meta_utils.py` | Построение SQL для incr/set/max/nested/remove операций |
| Парсинг сообщений и сопутствующих сущностей | `backup/messages_import.py` | Единый проход сообщений + реакции/аттачменты/emoji |
| Экспорт в Mattermost | `export/` | Оркестратор и экспортеры сущностей |

## Инварианты
* Ни один *_processed счётчик не уменьшается.
* messages стадия — единственная точка создания реакций / вложений / emoji ссылок.
* Консолидация totals выполняется один раз при переходе в exporting.
* Добавление новой сущности не должно требовать дополнительной стадии — интегрировать в существующий проход либо экспорт.
